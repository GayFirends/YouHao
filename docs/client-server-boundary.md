# 客户端与服务端分仓约定

本项目按“本地优先客户端 + 专用开源后端 + 官方公用实例 + 可选自建”的方向演进。服务端将放入用户另行创建的新仓库；新仓库名称和地址确定后再补充链接。

本文记录仓库职责与后续对接原则。当前应用仍使用本地 SQLite 和 WebDAV，账号登录及专用 API 同步尚未实现。

## 仓库职责

| 当前客户端仓库 `YouHao` | 后续独立服务端仓库 |
| --- | --- |
| Vue、Capacitor、Web 和 Android 界面 | TypeScript、Fastify 与 PostgreSQL |
| 本地 SQLite、迁移、离线录入、客户端写入一致性 | 账号认证、用户数据隔离、服务端数据迁移 |
| 本地备份、恢复、WebDAV 兼容 | 服务端版本、增量变更、操作去重、冲突历史 |
| 后续 API 客户端、同步状态、离线待提交操作 | 官方实例与自建实例共用的 API |
| 客户端构建、回归测试与 Android 发布 | Docker 部署、数据库备份恢复与服务监控 |

当前仓库不放服务端入口、服务端数据库模型、鉴权实现、容器部署或服务端依赖。两边独立构建和发布，不依赖另一仓库的本地目录。

## 当前客户端基础

- `src/services/database-adapter.ts` 是客户端 Web／Android 本地存储接口，不是网络 API 协议。
- `src/types/index.ts` 中的 `Vehicle`、`FuelRecord` 描述现有客户端实体，可作为未来协议设计的领域参考。
- `SyncPayload.version = 1` 是现有 JSON 备份与 WebDAV 快照格式；继续保持旧备份兼容，不把它直接改成服务端增量协议。
- 本地 SQLite 结构版本、IndexedDB 存储版本、备份格式版本、未来 API 版本分别演进。
- 在专用后端可对接之前，现有 WebDAV 同步继续提供服务。迁移为独立备份渠道需要配套导入与切换流程。

## 后续需要双方共同确定的同步约定

1. **本地优先**：业务写入与待提交操作在本地原子保存，断网期间继续使用；网络恢复后重试。
2. **增量与版本**：由服务端分配版本和同步游标，客户端提交所基于的版本。设备时间用于业务展示，不决定服务端并发更新的胜负。
3. **重试去重**：操作 ID 在重试期间保持不变；数据变更和去重结果一起提交，避免超时重发生成重复记录。
4. **冲突可恢复**：不同记录独立合并；同一记录的并发修改返回可识别的冲突，保留可恢复版本。删除需要传播，并有明确的回收站与保留策略。
5. **账号与实例隔离**：数据、令牌、游标及待提交操作按服务端实例和账号隔离。切换实例或账号时，不自动上传原账户的本地记录。
6. **单一主同步源**：每个账本选择一个主同步源。官方实例和自建实例遵循同一协议，WebDAV 可作为独立备份与迁移渠道。
7. **版本兼容**：服务端仓库确定可版本化的接口规范，客户端按发布的规范实现或生成类型；记录最低兼容版本及升级／重新同步策略。

接口路径、认证组件、请求结构和部署配置在服务端仓库建立后一起确定；当前不创建占位服务端或虚假的已登录／已同步功能。

## 推进顺序

1. 在客户端修复本地保存失败、多页面写入、已有 WebDAV 冲突判断，补上数据库迁移与故障回归测试。
2. 在新服务端仓库确定认证与同步契约，并建立版本化接口规范。
3. 客户端实现待提交队列、API 连接与登录、同步状态、实例切换和回收站；服务端实现对应能力。
4. 联调离线重试、冲突、删除、账号切换与旧客户端升级，验证备份恢复后再开放公用实例。
